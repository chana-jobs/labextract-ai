## 0. התחלה מהירה (Linux)
```bash
sudo apt-get install -y tesseract-ocr tesseract-ocr-heb tesseract-ocr-osd     # + Python 3.11
cd labextract_ocr_engine && python3.11 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python tests/smoke_test.py                                                     # expect 4/4
python run_extract.py samples/input/synth_00_L1_row_text.pdf --contract --out /tmp/labocr_out
```
את הפלט משווים ל-`samples/expected_output/`. בתוך ריפו ה-Backend אפשר לייבא את `shared.contracts` כמו שהוא. בכל מקום אחר מגדירים `LABOCR_CONTRACTS_REPO`.

## 1. איך מפעילים
- **שורת פקודה** (נקודת הכניסה היחידה):

  ```
  python run_extract.py <קובץ> [--pages 1,3] [--out DIR] [--overlay] [--contract]
  ```

  - **הפלט:** קובץ JSON עם תוצאת המנוע.
  - **עם `--contract`:** גם קובץ `forms.json` עם `shared.contracts.Form` מאומת לכל עמוד.
- **מתוך Python:** ‏`Engine().extract_file(...)` ואחריו `page_to_form(...)`.
- **שבעת השדות מופיעים תמיד:** שם פרטי, שם משפחה, ת"ז, תאריך קבלה, מוסד שולח, מספרים מרכזיים, מספרי התחייבות.
  - לכל שדה יש סטטוס: הוצע, לא ודאי, או חסר.
  - לכל שדה יש מועמדים עם ראיות וקואורדינטות, ואזורי בדיקה.
- **אין אישור אוטומטי.** כל ערך ממתין לאישור אנושי (PENDING).
- **עמוד שנכשל** מסומן FAILED, עם התקלה TECHNICAL_FAILURE, ולעולם לא "חסר". שאר העמודים ממשיכים.

## 2. כללים מחייבים ל-Backend
- **התחייבויות:** לצרוך רשומה נפרדת לכל שורה (`Examination.commitments[]`), ולא רק את `values` של הרשימה. ברשימה חלקית `values` ריק.
  - קיום השורה, מצב החילוץ ומצב האישור הם שלושה מצבים נפרדים.
  - `COMMITMENT_COUNT_UNCERTAIN` אומר שלא אושר שהרשימה שלמה.
- **אזורי בדיקה** (`review_region`) הם מקום להציג לבודקת, לא ערך.
- **מועמדי Gemini** מסומנים `gemini_htr`. ת"ז ושמות מ-Gemini הם תמיד לבדיקה בלבד.

## 3. תצורה
- **משתני סביבה בלבד, בלי נתיבים אישיים קשיחים:**
  - `LABOCR_TESSERACT` – נתיב ל-Tesseract.
  - `LABOCR_PADDLE_REPO` – תיקיית המודלים. ברירת המחדל: `vendor/paddleocr-hebrew` שבתוך החבילה.
  - הרשימה המלאה של המשתנים וברירות המחדל: `ENV_VARS.example` בחבילה, וטבלה 4 ב-`OCR_HANDOFF_EN.md`.
  - `LABOCR_CACHE` – זיכרון המטמון של ה-OCR. **מכיל טקסט של המטופלים, ויש להתייחס אליו כמידע רגיש.**
  - `LABOCR_CONTRACTS_REPO` – מיקום החוזים.
  - `LABOCR_GEMINI*` – הגדרות Gemini.
- **Gemini עובד רק כשכל אלה מתקיימים יחד:**
  - הרכיב מופעל;
  - מצב יבש כבוי;
  - נבחרה שליחה אמיתית;
  - מכסת קריאות גדולה מאפס;
  - אישור שאין חשבון חיוב;
  - מפתח מוגדר;
  - המסמך ברשימת המותרים. כרגע רק דגימות הפיתוח האנונימיות.
- **מסמכים אמיתיים:** שליחה שלהם ל-Gemini מחייבת אישור פרטיות נפרד.
